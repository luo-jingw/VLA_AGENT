# 静止帧与末尾补帧

## 为什么单独一步

示教中的静止段有几种完全不同的含义，留与删的影响也不同：

| 位置 | 含义 | 保留的影响 | 删去的影响 |
|---|---|---|---|
| 开头（第一次运动之前） | 操作者还没开始 | 模型学到"看到初始画面时等待"，部署时可能迟迟不动 | 只损失"开始运动"之前的几帧 |
| 关键帧窗口内 | 任务本身：抓取前稳住、等待密封 | 必须保留 | 会教模型在事件完成前就继续动作 |
| 其他中途停顿 | 犹豫，或关键帧定义尚未覆盖的等待 | 同一画面对应"不动"和"动"两种标签，监督互相矛盾 | 画面在删除处跳变，但标签更一致 |
| 结尾（最后一次运动之后） | 任务完成，手臂保持 | 教模型完成后保持 | 模型没学过完成后该做什么 |

很多录制在任务完成那一刻就停止，结尾没有静止段，模型从没见过"任务已完成"的画面。末尾补帧就是为此补上这类样本。

## 输入

清洗版数据集、S3 的 `keyframes_pass1.json`、`robot_spec.json`。工具：`vla_tools.episode_timing`。

## 步骤

### 1. 报告

```bash
python -m vla_tools.episode_timing --dataset data/<src>-clean --spec robot_spec.json --keyframes runs/<task>/keyframes_pass1.json \
    [--threshold 0.004 --min-frames 4]
```

列出每类静止段的数量、总帧数和最长长度。阈值（每帧最大关节变化）多试一两档：默认阈值下一段静止都没有，不代表没有短暂停顿。

同时检查结尾：释放类关键帧的相对位置接近 1，或者 `keyframe_detect` 报告窗口越界，都说明录制在任务完成时就停止了。

### 2. 决定

写 `timing_plan.json`。每个非空的决定都要在 `reasons` 里写理由，否则工具拒绝写出：

| 字段 | 取值 |
|---|---|
| `leading_keep` | 开头保留的静止帧数；`null` 全部保留 |
| `pause_keep` | 关键帧窗口外每段停顿保留的帧数；`null` 全部保留 |
| `trailing_keep` | 结尾保留的静止帧数；`null` 全部保留 |
| `end_padding` | 末尾追加的保持帧数；0 表示不补 |

关键帧窗口内的静止段始终保留。如果某段停顿其实是任务的一部分（例如等待加热），在关键帧定义里给它加一个类型，而不是在这里保留。

`end_padding` 的取值：至少覆盖一个完整的 chunk（span 帧），使最后一个真实帧的标签完全落在"保持"上；通常再留出约 1 秒。

### 3. 生成定时版

```bash
python -m vla_tools.episode_timing --dataset data/<src>-clean --spec robot_spec.json --keyframes runs/<task>/keyframes_pass1.json \
    --plan runs/<task>/timing_plan.json --out data/<src>-timed
```

补帧行的内容：动作保持最后一个目标，状态等于这个目标（手臂已到位），图像重复最后一帧，`is_padding = 1`。补帧之后：

- 用 `keyframe_review` 查看释放类关键帧在 +span 帧处的画面，确认最后一帧确实是"任务已完成"（物体已放好，末端已打开）。最后一帧如果还在动作中途，补出来的就是错误的样本，应减少补帧或排除该集。
- 在定时版上重新运行体检：补帧行不计入任何统计，体检结果应与清洗版相同。
- 关键帧要在定时版上重新检测（S5），之前的关键帧文件不能沿用。

补帧重复的是源 episode 的最后一行。`trailing_keep` 为 0 时，那一行是被删掉的结尾静止段的最后一帧，状态等于那时的目标，而不是最后保留的那一行；两者相差的是静止段里的漂移，补帧前后核对一次。

## UR3 上的结果（参考量级）

双臂 UR3 遥操作抓放，52 集，30 Hz，2026-10-26：

- 计划：静止阈值 0.002 rad / 帧、至少 5 帧；开头、中途、结尾的静止段都删去，只保留夹爪指令切换前 8 帧到后 15 帧之内的静止；末尾统一补 60 行（2 s）。0.001 和 0.003 rad 时删去的帧数在 ±3% 之内；
- 19,857 个录制行删去 5,413 行（开头 2,221、中途 1,343、结尾 1,849），每集保留中位 71%（52–85%）；
- 只有 1 段静止落进切换窗口，按规则整段保留（多出窗口 30 行）：遥操作时手臂在夹爪切换前后几乎一直在动；
- 删去静止段后，相邻真实行之间 `|action[t] − state[t+1]|` 最大 0.0064 rad，接到补帧时最大 0.0063 rad；
- 在定时版上重新检测：没有开头和中途的静止段，结尾只剩补帧。

## 限制

视频格式的数据集改变行需要重新编码视频，工具会拒绝执行。这种情况下，在转换成 LeRobot 之前处理静止帧和补帧。

## 停止条件

- 最后一帧画面不是"任务已完成"，补帧会制造错误样本；
- 视频数据集需要改变行。

## 完成标准

- `timing_plan.json`（每个决定都有理由）、定时版数据集、`meta/timing_report.json` 都存在；
- 定时版上的体检与清洗版一致，关键帧越界问题已消失或已解释。
