# 模型评估

评估分层进行，后一层不能替代前一层。所有误差都以录制的逐帧目标为参照，以帧运动量为单位，因此逐帧基线和重采样模型可以放在同一张表里比较。

## L0 放置误差下限（无模型）

`label_replay`（见 `vla-action-labels`）把标签当作完美模型的输出走一遍服务端插值，得到该配置在任何模型下都去不掉的误差和指令边沿偏移。L1 的 head 和拼接误差减去这一层，才是模型本身的误差。

## L1 留出集开环回放

每个模型各起一个新的服务进程（openpi `Policy` 的随机数从固定种子开始，同样的调用顺序下采样噪声可复现），然后：

```bash
python -m vla_tools.replay_eval --dataset data/<src>-<labels>-eval --spec robot_spec.json \
    --replay-spec runs/<task>/replay_spec.json --episodes <留出集> --execute <执行长度> \
    --host <server> --port 8000 --out runs/<task>/eval_<model>.json
```

| 列 | 含义 |
|---|---|
| points | 模型输出的点与标签点之差；只对重采样模型有，是纯模型误差 |
| head | 前 `--execute` 帧逐帧目标与录制之差，含模型误差和放置误差 |
| stitched | 每 `--execute` 帧重新推理、拼接后的逐帧误差；最接近机器人实际执行的结果 |
| edges | 每个录制指令边沿在拼接轨迹中的偏移，负值为提前 |
| static | 在静止维上下发的最大移动 |
| hold | 补帧行（任务已完成）上的拼接误差：模型完成任务后是否保持不动 |
| ms | 客户端往返延迟；JAX 下 openpi 的 `infer_ms` 只计到任务派发为止，不是计算时间 |

比较时固定 episode、`--execute` 和服务端硬件，只换模型。把各模型的 `all` 行合成一张表，再给出结论和置信度。

L1 反映不了闭环中误差累积后的行为。在训练集上做 L1 只能说明链路可用。

## L1 按覆盖解读

```bash
python -m vla_tools.coverage_eval --diversity runs/<task>/diversity.json --eval baseline=eval_a.json candidate=eval_b.json
```

逐集列出到最近训练 episode 的距离和各模型的误差。距离大的留出集误差显著变大，说明模型依赖的是覆盖范围，而不是学到了泛化能力。数据覆盖本身有限时（见 `vla-data-diversity` 的结论），报告中要写明结论的适用范围。

## L2 机器人闭环

所有模型使用同一协议：

- 同一组初始摆放，包括训练覆盖内和覆盖外的；每个模型相同的试验次数；同样的执行长度和控制频率；
- 记录成功率（附 Wilson 置信区间），以及失败发生在哪个阶段（与关键帧阶段对应）；
- 指令时机：是否在到位前闭合或释放，对应 L0/L1 的边沿偏移；
- 完成后是否保持不动，对应 hold；
- 重新规划时是否有停顿或跳动；
- 推理延迟是否小于执行长度对应的时间（`execute / fps`）。

## UR3 上的观测（参考量级）

已训练的 `curvature`、span 20 模型（训练时用了全部 22 集，所以下面不算留出评估），在 4 集上执行 6 帧：
- head 1.58、拼接 1.00 帧运动量；
- 夹爪边沿提前 1–2 帧；
- 补帧行上的 hold 为 0.49 帧运动量：模型没见过任务完成后的画面，有小幅漂移。

## 停止条件

- 没有留出集，却要得出模型优劣的结论；
- 各模型的评估条件不同（episode、执行长度、硬件）。

## 完成标准

- 对比表、逐集覆盖表和 L0 下限都已记录；
- 结论附置信度，未观测的内容已列出；
- 已验证的结论写入 `docs/`。
