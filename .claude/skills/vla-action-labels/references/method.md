# 方法定义

## 术语

| 术语 | 定义 |
|---|---|
| 录制帧 | 数据集里的一行。`state[t]` 是第 t 帧的状态，`action[t]` 是到第 t+1 帧要达到的目标，即 `action[t] ≈ state[t+1]` |
| 关节维 / 指令维 | 连续位置量 / 0-1 指令，见 `robot_spec.json` |
| 进度 `s(t)` | 对每帧增量 `ds` 的累加，单调不减；在 `s` 上等间隔取点 |
| 跨度 `span_frames` | 一个 chunk 的 H 个点平均覆盖的帧数；服务端按 span 帧把 H 个点展开成逐帧目标 |
| 覆盖帧数 reach | 从当前状态到最后一个点实际跨过的录制帧数（`sweep` 的 `reach` 列） |
| 关键帧窗口 | 来自 `keyframes.json`，每个关键帧前后的一段帧 |
| 路径步长 | 录制中相邻两帧关节位置欧氏距离的中位数，不计距离为 0 的帧（补帧行、重复帧）；路径类误差除以它，读作"相当于几步" |
| 参考步长 | 同一组非零步长的 95 分位，速度比的分母 |
| 帧运动量 | 逐帧最大单关节变化量的中位数；体检以它为单位，标签打分中只用于 `sweep.json` 里按时间对齐的参考量 |

## 标签

对每个录制帧 t：

1. 每帧进度增量：
   - 关键帧窗口内、且 `event_density > 0`：`step · event_density / (span/H)`，即窗口内按时间均匀取点，密度是窗口外的 `event_density` 倍；
   - 其他位置：`max(raw − deadzone, 0)`，`raw` 由度量决定（见下节）。
2. `step` 取值使窗口外平均每 `span/H` 帧一个点。平均按 episode 的全部行计算，包括补帧行和静止帧。
3. 起点 `a(t)`：当前状态的进度 `s(t−1)`（`anchor="state"`）。`state[0]` 之前没有动作，按第一帧的增量向前外推。
4. 第 k 个点（k = 1…H）的进度为 `a(t) + k·step`。反查得到小数帧位置后取值：关节维用 PCHIP（经过每个录制样本，不过冲），指令维取最近一帧并取整为 0/1。
5. 超出 episode 末尾的点钳制到最后一帧，loss 权重为 `pad_weight`。
6. 取自关键帧窗口的点，loss 权重为 `key_weight`；它与 `event_density` 相互独立。

`time` 度量、`span = H`、`anchor="state"` 时，标签与逐帧 chunk `action[t : t+H]` 完全相同（UR3 数据上 3003 帧最大差 4e-9）。

## 度量

| 度量 | `raw`（第 i 帧到第 i+1 帧） | 点落在哪里 | 服务端能否知道点的时间 |
|---|---|---|---|
| `time` | 1 | 时间上等间隔 | 能，第 k 点恰在 `k·span/H` 帧 |
| `curvature` | `max(c(i), curvature_floor · c̄) · ℓ(i)` | 转弯处密，直线处稀；与示教速度无关 | 不能，只能假定 |
| `second_difference` | `‖q[i+1] − 2q[i] + q[i−1]‖^(1/3)` | 加速度大处密；随示教速度变化 | 不能，只能假定 |

`curvature` 的各项：

- `ℓ(i) = ‖q[i+1] − q[i]‖`，关节空间欧氏距离；
- `κ` 是关节路径的几何曲率（`path_curvature.curvature`）：在样本 i 处，向后、向前各取一段弧长至少为 W 的弦 `u = q[i] − q[j]`、`v = q[k] − q[i]`，`κ(i) = ∠(u, v) / ((S[k] − S[j]) / 2)`，S 为累计弧长。弦端由弧长而不是帧号决定，所以静止帧不增加弧长，也不产生虚假曲率；半径 R 的圆上 `κ = 1/R`；
- `W = curvature_window ×`（该 episode 非零逐帧步长的中位数），默认 4 步；
- `c(i) = ((κ[i] + κ[i+1]) / 2)^(1/3)`，`c̄` 为 c 按 ℓ 加权的 episode 均值；`curvature_floor` 默认 0，此时严格直线段不增加进度，立方根让接近直线的段仍有进度。

每单位路径长度的进度只取决于路径形状：圆上为 `R^(−1/3)`，与走过它的速度无关。测得值：

| 检查 | 结果 |
|---|---|
| 圆（R = 0.1、0.2、0.4，速度 0.25–1.75 倍变化），每单位长度进度 vs `R^(−1/3)` | 最大相对误差 8.1e-6 |
| 从静止加速走过的直线，每单位长度 raw | `curvature` 7.1e-5，`second_difference` 10.3 |
| 同一条折线路径以三种速度曲线录制（匀速 v、匀速 2v、加减速带停顿），归一化进度最大差 | 0.0072 |
| LIBERO 50 条示教，同一关节路径换匀速 / 2 倍速 / 0.4–1.6 倍正弦变速重新计时，归一化进度最大差的中位数 | `curvature` 0.0040 / 0.0162 / 0.0035；`second_difference` 0.0443 / 0.0479 / 0.0486 |

窗口 W 以 episode 自身的步长为单位，示教整体变快时 W 随之变宽，曲率变化处的平滑宽度也随之改变；用录制时的绝对弧长窗口计算，2 倍速一栏的中位数为 0.0087。见 `issues.md` 的 ISSUE-001。

`second_difference` 用于复现用它构建的数据集。只写了 `metric: "curvature"`、没有 `curvature_window` 的配置是用二阶差分构建的，`ResampleConfig.from_dict` 拒绝读取并提示改为 `second_difference`；未知的度量名同样拒绝。

进度度量把监督点从停顿和直线段挪到改变方向的地方，代价是丢掉了每个点的时间：服务端只能按 `k·span/H` 帧放点。静态任务里沿路径的快慢不影响结果，影响结果的是执行目标走过的路径和指令在哪里切换，`sweep` 和 `label_replay` 按这两点打分（见下节）。

几何度量下补帧行和静止帧不增加进度，而 `step` 按全部行平均，所以一个 span 覆盖的录制帧少于 span，服务端仍按 span 帧展开，执行比录制慢。LIBERO（每集 135–195 行加 40 行补帧）上 `curvature` span 40 的覆盖帧数中位 26.5–30.2，闭环回放的执行帧数是录制帧数的 1.45–1.58 倍；跨度量比较时看 reach，不看 span。见 ISSUE-002。

## 打分

### 网格搜索（`sweep`）

每个格子在第 `--stride` 个录制帧上取标签，按服务端的方式放点（`arc_interp.to_frames`），与录制比较几何，不按逐帧时间对齐。标签含补帧点的帧不计入。

| 列 | 定义 |
|---|---|
| path head / path full | 前 `--head` 个 / 全部执行目标到录制路径段的最大距离；路径段为当前状态的关节位置加上 `action[t]` 到最后一个标签点之后 3 帧。中位 / p90，路径步长 |
| kf position | `--head` 帧内每个录制的指令边沿：指令第一次切换处的执行目标与边沿处录制关节位置的距离（从同一指令维上一个边沿之后的中点开始找）。中位 / p90，路径步长 |
| kf missed | 执行的 chunk 内指令始终没有切换的边沿数 |
| speed | [当前状态, 前 `--head` 个目标] 上的最大单帧步长 / 参考步长。中位 / p95 |
| jump | 第一个点离当前状态的距离，路径步长 |
| pad | 超出 episode 末尾的点所占比例 |
| kept | 至少出现在某一帧标签里的指令边沿 / 全部边沿 |

可接受：path head 中位 ≤ `--max-head`（默认 1），kf position 中位 ≤ `--max-kf`（默认 1；没有边沿时不检查），所有边沿都保留；给定时还要满足 speed p95 ≤ `--max-speed-ratio`、jump ≤ `--max-jump`（运控上限）、pad ≤ `--max-pad`。选择：取有可接受格子的最大 span，再在同一 span 内取 path full 中位最小者（相同时比 path head 中位）。每个 span 的最佳可接受格子构成候选清单。

`sweep.json` 另外保留按时间对齐的参考量：`true_err`（点放在真实时间）、`head_err`、`full_err`（点放在假定时间）与 `action[t+j]` 逐帧比较的最大单关节误差，以及 `edge_shift`（指令边沿的时间偏移，帧）。它们不参与可接受和选择。

### 标签闭环回放（`label_replay`）

把标签当成完美模型的输出，逐集从第 0 帧开始闭环执行：

1. 取当前观测帧的标签，按服务端规则展开成逐帧目标，执行前 e 个；
2. 以最后一个执行目标为当前位姿，在录制中重新观测：从上次观测帧往后找，最远到标签最后一个点之后 3 帧，只在录制指令状态与执行指令状态相同的帧中，取关节距离最近的一帧；距离相同（静止段）时取最接近"上次观测 + e"的帧；
3. 重复，直到观测到最后一个录制帧。

| 列 | 定义 |
|---|---|
| path | 每个执行目标到它所在 chunk 的录制路径段的距离：中位 / p90 / 最大 |
| seam | 上一 chunk 最后一个执行目标到下一 chunk 第一个目标的距离：中位 / 最大，路径步长 |
| kf position / missed | 每个录制的指令边沿：执行序列里对应那次切换处的目标与边沿处录制关节位置的距离；没有切换的边沿计入 missed |
| hold | 每次指令切换前后，执行目标停在切换点 1/4 路径步长以内的帧数：中位 / 最小 |
| speed | 每集执行目标的最大单帧步长 / 参考步长：中位 / 最大 |
| infer, frames | 推理次数；执行帧数 / 录制帧数 |

`time`、`span = H` 时标签就是录制本身：路径偏差为 0，每次观测恰好前进 e 帧。

## 关键帧窗口的两个开关

- `event_density`：窗口内点密度相对窗口外的倍数。0 表示窗口不改变间距，1 表示与周围相同。服务端按均匀时间放点，所以密度不等于 1 时，窗口内的时间被拉伸或压缩：比周围稀时指令提前切换，比周围密时推后切换，并在切换点附近停留更久。切换处的位置取自录制路径，窗口内点越密，切换点离录制边沿越近。UR3 上按时间对齐测得：窗口内固定 3 个点（相当于密度约 0.46）使夹爪提前 2–3 帧，密度 2 推后 2 帧。LIBERO 上按几何测得：密度 2 在 `curvature` 的每个 span 都降低了关键帧位置误差（`curvature` span 40：中位 0.30 路径步长，密度 0 时 0.48），闭环回放中每次指令切换处停留 2–3 帧，逐帧基线为 1 帧。
- `key_weight`：取自窗口的点在 loss 中的倍数，不改变点的位置。需要强调关键时刻时用这个。

## 存储

在原数据集的每一行后追加两列：

| 列 | 形状 | 含义 |
|---|---|---|
| `action_chunk` | (H·D,) | 这一帧的 H 个点，展平 |
| `action_loss_weight` | (H,) | 每个点的 loss 倍数 |

标签必须在构建时算好存进去：数据加载器按 `delta_timestamps` 取的是时间上等间隔的切片，而进度到帧的映射在每一帧都不同，切片表达不了。行数、观测和原有各列都不变。图像以 PNG 存在 parquet 里时，读写走 `datasets` 库，以保留声明图像列的 `huggingface` schema。

## 不变量

- 每行仍对应一个录制帧（或带 `is_padding` 标记的补帧），观测未被修改；
- 标签中的指令维只取 0 或 1；
- 每个录制的指令边沿至少出现在某一帧的标签里；
- 训练所用的 `anchor`、span、H 与服务端一致，都来自同一份 `arc_resample.json`。
