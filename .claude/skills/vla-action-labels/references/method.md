# 方法定义

## 术语

| 术语 | 定义 |
|---|---|
| 录制帧 | 数据集里的一行。`state[t]` 是第 t 帧的状态，`action[t]` 是到第 t+1 帧要达到的目标，即 `action[t] ≈ state[t+1]` |
| 关节维 / 指令维 | 连续位置量 / 0-1 指令，见 `robot_spec.json` |
| 重建 | 部署时从当前位姿和模型输出的 H 个点插值出逐帧目标：not-a-knot 三次样条，节点在服务端假定的点时刻（`arc_interp`） |
| 窗口 | 第 t 帧的窗口：从当前状态开始的 `span_frames` 个录制段 |
| 进度 | 按度量对每段的增量累加，单调不减；在窗口内按进度等间隔放点 |
| 跨度 `span_frames` | 每帧窗口覆盖的录制帧数；窗口内没有关键帧时，第 H 个点恰好落在窗口末端 |
| 执行倍速 r | 部署参数：服务端把 H 个点展开成 span / r 帧的逐帧目标；r = 1 时不含关键帧的窗口按录制的节奏执行 |
| 覆盖帧数 reach | 从当前状态到最后一个点实际跨过的录制帧数（`sweep` 的 `reach` 列） |
| 关键帧窗口 | 来自 `keyframes.json`，每个关键帧前后的一段帧 |
| 路径步长 | 录制中相邻两帧关节位置欧氏距离的中位数，不计距离为 0 的帧（补帧行、重复帧）；路径类误差除以它，读作"相当于几步" |
| 参考步长 | 同一组非零步长的 95 分位，速度比的分母 |
| 帧运动量 | 逐帧最大单关节变化量的中位数；体检以它为单位，标签打分中只用于 `sweep.json` 里按时间对齐的参考量 |

## 标签

标签是 H 个稀疏点，部署时服务端用它们插值重建轨迹（见“部署”和“从稀疏点重建的选择”）。每个 episode 分两步：

1. **切窗口**：段 i 连接动作行 i 和 i+1。第 t 帧的当前状态是动作行 t−1（`anchor="state"`；第 0 帧之前补一个复制第 0 段的虚拟段），窗口是从它开始的 `span_frames` 个段中位于录制行之间的部分。
2. **在窗口内稀疏取点**：
   - 每段的自由进度 `free(i) = max(raw(i) − deadzone, 0)`，`raw` 由度量决定（见下节）；关键帧窗口内、且 `event_density > 0` 的段不计自由进度，单独处理；
   - 这一帧的步长 `step(t) = A · (span/H) / N`，A 是窗口内录制行之间的非关键帧段的自由进度之和，N 是这些段的数目：窗口的自由部分平均每 `span/H` 帧一个点；
   - 关键帧段的进度为 `step(t) · event_density / (span/H)`：每 `span/H` 帧 `event_density` 个点，按时间均匀，不受窗口其余部分影响；
   - 窗口内没有自由进度（A = 0，完全静止或全是关键帧段）时，这一帧按时间取点：录制行之间的自由段每段 1，补帧段按各自的度量，关键帧段每段 `event_density`，`step = span/H`；
   - 第 k 个点（k = 1…H）在这一帧的累计进度 `s_t(起点) + k · step(t)` 处，反查得到小数帧位置（段内线性；落在平台上即静止段时取平台的第一行），关节维在相邻两个录制行之间线性取值（点都在录制路径上，最后一个录制行之后取该行），指令维取最近一行并取整为 0/1。

结果：

- 窗口内没有关键帧段、且整个窗口在录制行之内时，第 H 个点恰好是窗口末端的录制位置；
- `event_density > 1` 时，含关键帧段的窗口覆盖不满 span 帧，服务端在关键帧附近相应放慢；
- 超出最后一个录制行的点落在最后一行，记为补帧点，loss 权重为 `pad_weight`；
- 取自关键帧窗口的点，loss 权重为 `key_weight`；它与 `event_density` 相互独立。

`time` 度量、`span = H`、`anchor="state"` 时，标签与逐帧 chunk `action[t : t+H]` 完全相同（UR3 数据上 3003 帧最大差 4e-9；LIBERO `time` span 10 重建后与旧数据集逐元素相差 ≤ 9.3e-10，即 float32 存储的末位）。

### 从稀疏点重建的选择

部署时只有当前位姿和 H 个点，轨迹从这 H+1 个节点插值重建。候选：折线，或 PCHIP / not-a-knot 三次样条配一种节点参数（均匀 k，即服务端的点时刻；累计弦长；弦长平方根即向心；点在录制里的真实行号，服务端拿不到）。LIBERO 50 条示教（`sparse_rebuild_check.py`），每个不含补帧点的帧取录制行到重建曲线、重建曲线到录制路径两个距离中的较大者，以路径步长计，中位 / p90 / 最大：

| 从 10 个点重建 | `curvature` s40 密度 2 | `curvature` s40 密度 0 |
|---|---|---|
| 折线 | 0.22 / 0.37 / 0.99 | 0.34 / 0.74 / 1.36 |
| PCHIP，均匀 | 0.12 / 0.25 / 0.78 | 0.24 / 0.62 / 1.24 |
| **三次样条，均匀** | **0.09 / 0.21 / 0.72** | **0.17 / 0.45 / 0.76** |
| PCHIP，弦长 | 0.12 / 0.26 / 0.82 | 0.25 / 0.65 / 1.28 |
| 三次样条，弦长 | 0.11 / 0.30 / 1.41 | 0.22 / 0.73 / 2.40 |
| 三次样条，向心 | 0.09 / 0.21 / 0.71 | 0.19 / 0.56 / 1.13 |
| PCHIP，真实行号 | 0.12 / 0.25 / 0.76 | 0.24 / 0.60 / 1.22 |
| 三次样条，真实行号 | 0.08 / 0.18 / 2.67 | 0.16 / 0.42 / 4.42 |

插值方式比节点参数重要：均匀节点和真实行号几乎一样，弦长参数的尾部最大。`arc_interp` 用均匀节点上的三次样条；曲率标签的点在曲率进度上等距，均匀节点就是按曲率进度参数化。三次样条的单个关节会越出相邻两节点的范围（密度 2：中位 0.06、最大 0.53 路径步长），录制行在同一对节点之间越出得更多（中位 0.06、最大 0.66），即样条跟着录制路径本身的弯；PCHIP 按构造不越出，所以在弯处抄近路。标签点在相邻录制行之间线性取值，离录制折线 ≤ 4.7e-16 rad，重建只有这一处插值。

## 度量

| 度量 | `raw`（第 i 帧到第 i+1 帧） | 点落在哪里 | 服务端能否知道点的时间 |
|---|---|---|---|
| `time` | 1 | 时间上等间隔 | 能，倍速 1 时第 k 点恰在 `k·span/H` 帧 |
| `curvature` | `max(c(i), curvature_floor · c̄) · ℓ(i)` | 转弯处密，直线处稀；与示教速度无关 | 不能，只能假定 |
| `second_difference` | `‖q[i+1] − 2q[i] + q[i−1]‖^(1/3)` | 加速度大处密；随示教速度变化 | 不能，只能假定 |

`curvature` 的各项：

- `ℓ(i) = ‖q[i+1] − q[i]‖`，关节空间欧氏距离；
- `κ` 是关节路径的几何曲率（`path_curvature.curvature`）：在样本 i 处，向后、向前各取一段弧长至少为 W 的弦 `u = q[i] − q[j]`、`v = q[k] − q[i]`，`κ(i) = ∠(u, v) / ((S[k] − S[j]) / 2)`，S 为累计弧长。弦端由弧长而不是帧号决定，所以静止帧不增加弧长，也不产生虚假曲率；半径 R 的圆上 `κ = 1/R`；
- 弦长 `W = curvature_length`（rad），对所有 episode 固定；`sweep` 默认取 4 个路径步长并打印；κ 只在录制行上计算，补帧段的进度为 0；
- `c(i) = ((κ[i] + κ[i+1]) / 2)^(1/3)`，`c̄` 为 c 按 ℓ 加权的 episode 均值；`curvature_floor` 默认 0，此时严格直线段不增加进度，立方根让接近直线的段仍有进度。

每单位路径长度的进度只取决于路径形状：圆上为 `R^(−1/3)`，与走过它的速度无关。测得值：

| 检查 | 结果 |
|---|---|
| 圆（R = 0.1、0.2、0.4，速度 0.25–1.75 倍变化），每单位长度进度 vs `R^(−1/3)` | 最大相对误差 8.1e-6 |
| 从静止加速走过的直线，每单位长度 raw | `curvature` 5.3e-5，`second_difference` 10.3 |
| 同一条折线路径以三种速度曲线录制（匀速 v、匀速 2v、加减速带停顿），归一化进度最大差 | 0.0027 |
| LIBERO 50 条示教，同一关节路径换匀速 / 2 倍速 / 0.4–1.6 倍正弦变速重新计时，归一化进度最大差的中位数 | `curvature` 0.0036 / 0.0082 / 0.0036；`second_difference` 0.0443 / 0.0479 / 0.0486 |

弦长固定后，示教整体变快不再改变平滑宽度。弦长若取每个 episode 中位步长的 4 倍，折线上三种速度的差为 0.058，LIBERO 2 倍速一栏为 0.0162。在经过每个录制行的插值曲线上加密采样再算曲率，折线上的差为 0.010–0.018，不比直接用录制行好。2 倍速一栏剩下的 0.8% 来自采样变粗（帧数减半）。

`second_difference` 用于复现用它构建的数据集。只写了 `metric: "curvature"` 的旧配置有两种：带 `curvature_window`（按 episode 中位步长定弦长、全集共用步长）或什么都不带（二阶差分），`ResampleConfig.from_dict` 都拒绝读取并说明原因；新建 `curvature` 配置必须给 `curvature_length`；未知的度量名同样拒绝。

进度度量把监督点从停顿和直线段挪到改变方向的地方，代价是丢掉了每个点的时间：服务端按 `k·span/(H·r)` 帧放点（见“部署”一节）。静态任务里沿路径的快慢不影响结果，影响结果的是执行目标走过的路径和指令在哪里切换，`sweep` 和 `label_replay` 按这两点打分（见下节）。

几何度量下静止帧不增加进度，补帧行不在任何窗口的步长里。LIBERO（每集 135–195 行加 40 行补帧）上 `curvature` span 40：密度 0 时每一帧的第 10 个点都恰好覆盖 40 个录制帧；密度 2 时覆盖帧数 p05 22.9、中位 33.6、p95 40.0（`time` 密度 2 中位 34.0），1685 个不含关键帧的窗口末端误差 ≤ 4.3e-14 帧。同一条示教补 10 行和补 40 行，录制行上的进度、每帧步长和不含补帧点的标签都完全相同。

## 部署：执行倍速

服务端（`arc_interp.ArcInterpolator`）把第 k 个点放在 `(offset + k·span/H) / r` 帧（`anchor="state"` 时 offset = 0，`"action"` 时 1），以当前位姿和 H 个点为节点，用 not-a-knot 三次样条插出逐帧目标，共 ⌊span / r⌋ 个；节点不足 4 个时为过两点的直线或过三点的抛物线。

- r 是部署参数：`ArcInterpolator.from_report(path, rate)`、`vla_openpi.launch.serving_config / serve(..., rate)`，默认 1；`arc_resample.json` 不记录它，标签和训练与 r 无关。
- 节点时间整体缩放不改变三次样条的形状：倍速 2 的第 j 个目标等于倍速 1 的第 2j+1 个目标（测试中差 0）。r 改变的只是走完同一条路径用的帧数和每帧的步长。
- 每块 ⌊span / r⌋ 个目标，执行长度 e 不超过它。
- 选 r：用 `rate_ceiling` 在部署的推理延迟下搜索 r 和执行长度 e，按关节速度上限、指令边沿和闭环路径偏差判断可行（见“倍数上限”一节）；路径偏差、关键帧位置在不同 r 下应基本不变。
- r = 1 时每个不含关键帧的窗口用 span 帧走完 span 个录制帧，即按录制的节奏；窗口内几何度量在弯道处慢、平缓处快，`time` 跟随录制逐帧的节奏；关键帧窗口加密的部分慢一些。

LIBERO，`curvature` span 40，e = 10（录制完成帧数 7702）：密度 2 时倍速 1 用 9485 帧完成、倍速 2 用 4725 帧，倍速 2 时速度比中位 1.89、最大 2.82，路径偏差最大 0.43 和 0.47 路径步长；密度 0 时倍速 1 用 8162 帧、倍速 2 用 4007 帧。

## 打分

### 网格搜索（`sweep`）

每个格子在第 `--stride` 个录制帧上取标签，按服务端的方式放点（倍速 1，`arc_interp.to_frames`），与录制比较几何，不按逐帧时间对齐。标签含补帧点的帧不计入。

| 列 | 定义 |
|---|---|
| path head / path full | 前 `--head` 个 / 全部执行目标到录制路径段的最大距离；路径段为当前状态的关节位置加上 `action[t]` 到最后一个标签点之后 3 帧。中位 / p90，路径步长 |
| kf position | `--head` 帧内每个录制的指令边沿：指令第一次切换处的执行目标与边沿处录制关节位置的距离（从同一指令维上一个边沿之后的中点开始找）。中位 / p90，路径步长 |
| kf missed | 执行的 chunk 内指令始终没有切换的边沿数 |
| speed | [当前状态, 前 `--head` 个目标] 上的最大单帧步长 / 参考步长。中位 / p95 |
| jump | 第一个点离当前状态的距离，路径步长 |
| pad | 超出 episode 末尾的点所占比例 |
| kept | 至少出现在某一帧标签里的指令边沿 / 全部边沿 |

可接受：path head 中位 ≤ `--max-head`（默认 1），kf position 中位 ≤ `--max-kf`（默认 1；没有边沿时不检查），所有边沿都保留；给定时还要满足 speed p95 ≤ `--max-speed-ratio`、jump ≤ `--max-jump`（运控上限）、pad ≤ `--max-pad`。选择：取有可接受格子的最大 span，再在同一 span 内取 path full 中位最小者（相同时比 path head 中位）。每个 span 的最佳可接受格子构成候选清单。

`sweep.json` 另外保留按时间对齐的参考量：`true_err`（点放在真实时间）、`head_err`、`full_err`（点放在假定时间）与 `action[t+j]` 逐帧比较的最大单关节误差，以及 `edge_shift`（指令边沿的时间偏移，帧）。它们不参与可接受和选择。

### 标签闭环回放（`label_replay`）

把标签当成完美模型的输出，逐集从第 0 帧开始闭环执行：

1. 取当前观测帧的标签，按服务端规则以倍速 r（`--rate`，默认 1）展开成逐帧目标，执行前 e 个；
2. 以最后一个执行目标为当前位姿，在录制中重新观测：从上次观测帧往后找，最远到标签最后一个点之后 3 帧，只在录制指令状态与执行指令状态相同的帧中，取关节距离最近的一帧；距离相同（静止段）时取最接近“上次观测 + round(r·e)”的帧；
3. 重复，直到观测到最后一个录制帧；最后一个录制帧的 chunk 一定执行，之后一直观测这一帧，直到执行位姿离最后一个录制行不超过结束容差（0.25 路径步长）且指令状态相同。

完成帧数：一个逐帧序列走到最后一个录制行、并从此一直停在结束容差以内所用的帧数。执行目标（含停留帧）和录制动作按同一规则计数，结束后停留的帧不计入。

每次重新观测至少前进一个录制帧。执行的 e 个目标不到一帧路径时（e 很小、倍速 1、关键帧窗口内），观测跑到执行位姿前面，这一行高估误差：LIBERO 上 `curvature` span 40 密度 2、e = 1、倍速 1 的路径偏差最大 1.97 路径步长，e = 2–40 为 0.42–0.57。见 ISSUE-004。

| 列 | 定义 |
|---|---|
| path | 每个执行目标到它所在 chunk 的录制路径段的距离：中位 / p90 / 最大 |
| seam | 上一 chunk 最后一个执行目标到下一 chunk 第一个目标的距离：中位 / 最大，路径步长 |
| kf position / missed | 每个录制的指令边沿：执行序列里对应那次切换处的目标与边沿处录制关节位置的距离；没有切换的边沿计入 missed |
| hold | 每次指令切换前后，执行目标停在切换点 1/4 路径步长以内的帧数：中位 / 最小 |
| speed | 每集执行目标的最大单帧步长 / 参考步长：中位 / 最大 |
| infer, frames | 推理次数；执行目标的完成帧数 / 录制动作的完成帧数 |

`time`、`span = H` 时标签就是录制本身：倍速 1 时路径偏差为 0，每次观测恰好前进 e 帧，完成帧数等于录制的完成帧数；倍速 2 时目标恰好落在每隔一帧的录制帧上，每次观测前进 2e 帧。

推理延迟 d = ⌈L · fps⌉ 个控制帧（`closed_loop` 的 `latency_frames`）：

- 同步：每次观测后机器人停 d 帧，再执行 e 个目标；
- 异步：每 e 帧观测一次（e ≥ d，同时只有一次推理在进行），它的 chunk 在 d 帧后到达，服务端从到达时的指令位姿重建（`arc_interp.after_latency`：保留时间减 d 后超过半个点距的点，时间减 d，同样的 not-a-knot 样条），执行到下一个 chunk 到达；第一个 chunk 从观测位姿展开，机器人先停 d 帧；chunk 用完时停在它的最后一个目标；延迟后一个目标都不剩的倍速不能运行。

### 倍数上限（`rate_ceiling`）

在给定推理延迟 L 和执行方式（异步、同步）下，标签作为完美模型的输出，机器人在关节速度上限内能达到的最大任务加速比。对每个标签配置、每个 L 和执行方式，逐集在倍速网格（1、1.5、2、3、4、6、8、12、16）和执行长度上闭环回放：异步 e 取 max(d, 1)、延迟后剩余目标的一半和全部，同步 e 取 chunk 的一半和全部；某集连续两个倍速都没有不超速的运行时停止向上搜索。

一次运行可行，当且仅当：

| 条件 | 定义 |
|---|---|
| 速度 | [第一个观测位姿, 全部执行目标（含停留和 chunk 切换）] 按数据集帧率差分，每个关节 \|Δq · fps\| 不超过它的速度上限 |
| 指令 | 每个录制的指令边沿都被执行 |
| 路径 | 每个执行目标到它所在 chunk 的录制路径段的距离不超过路径上限（`--path-bound`，默认 2 个路径步长） |

加速比 = 录制动作的完成帧数 / 执行目标的完成帧数。录制本身已超过速度上限的 episode 不参与，单独列出。结果：可行集数不少于 `--feasible-fraction`（默认 90%）的 (r, e) 中加速比最大者，加速比只在这些可行 episode 上求和，不可行的 episode 列出；另给每集最大可行倍速和每集最大可行加速比（各自选 e）的中位数和 p10，以及下一个网格倍速上失败的条件计数。只报告不约束：加速度占名义上限的比例（实机控制器可调）、chunk 切换处的单帧步长。路径步长和曲率弦长按全部 episode 计算，与 `sweep` 相同。

90% 结果落在阈值上：选中的设置通常恰好有 90% 的集可行，某个网格倍速多一集或少一集，结果就在相邻延迟之间跳动；每集中位数随延迟平滑变化，两者一起看。

## 关键帧窗口的两个开关

- `event_density`：关键帧窗口内每 `span/H` 个录制帧放几个点，按时间均匀，与所在窗口其余部分的形状无关（构造路径上窗口内点距与 `(span/H) / event_density` 的差 ≤ 5.7e-14）。0 表示窗口不单独处理，按度量取点；1 与自由部分的平均密度相同。服务端按均匀时间放点，所以密度大于 1 时窗口内的时间被拉长：指令推后切换，并在切换点附近停留更久；小于 1 时相反。切换处的位置取自录制路径，窗口内点越密，切换点离录制边沿越近。UR3 上按时间对齐测得：窗口内固定 3 个点（相当于密度约 0.46）使夹爪提前 2–3 帧，密度 2 推后 2 帧。LIBERO 上按几何测得：密度 2 在 `curvature` 的每个 span 都降低了关键帧位置误差（`curvature` span 40：中位 0.30 路径步长，密度 0 时 0.88），倍速 1 的闭环回放中每次指令切换处停留 2–3 帧，倍速 2 时 1 帧，逐帧基线为 1 帧。
- `key_weight`：取自窗口的点在 loss 中的倍数，不改变点的位置。需要强调关键时刻时用这个。

## 存储

在原数据集的每一行后追加两列：

| 列 | 形状 | 含义 |
|---|---|---|
| `action_chunk` | (H·D,) | 这一帧的 H 个点，展平 |
| `action_loss_weight` | (H,) | 每个点的 loss 倍数 |

标签必须在构建时算好存进去：数据加载器按 `delta_timestamps` 取的是时间上等间隔的切片，而进度到帧的映射在每一帧都不同，切片表达不了。行数、观测和原有各列都不变。图像以 PNG 存在 parquet 里时，读写走 `datasets` 库，以保留声明图像列的 `huggingface` schema。

## 不变量

- 每行仍对应一个录制帧（或带 `is_padding` 标记的补帧），观测未被修改；
- 标签中的指令维只取 0 或 1；
- 每个录制的指令边沿至少出现在某一帧的标签里；
- 训练所用的 `anchor`、span、H 与服务端一致，都来自同一份 `arc_resample.json`；执行倍速只在服务端设置。
